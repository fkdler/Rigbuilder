# 对话路由与指定硬件

自动模式的处理顺序为：读取同一对话最近的推荐需求 → agent-b 结构化预分析 → 规则保护 → 快速问答或数据库核验与配置融合。

`ROUTING_PROFILE_ID=agent-b` 应对应 Qwen3.5 4B Q6；agent-a 对应 Qwen3 8B Q4。预分析使用现有推理调度器，不与正在执行的融合任务争用模型。`ROUTING_ANALYSIS_ENABLED` 默认开启，`ROUTING_TIMEOUT_SECONDS` 默认 20 秒（不包括排队时间）。显式 FAST 和“不要查库”仍尊重用户选择。

分析输出短执行计划：任务类型（推荐／介绍／解释／闲聊）、目标范围（单件／整机）、CPU/GPU 目标、用途、性能偏好、介绍对象，以及是否需要数据库、是否延续需求。Schema 要求所有字段输出，最多 320 tokens；不生成产品事实或 SQL。计划通过请求局部上下文传给检索、两路模型选择、核验和展示，不靠“一个”等数量词判断范围。模型不能把规则已识别的配置请求降级；分析超时或格式错误保守转入核验。任务记录包含 `routing_analysis` 和 `effective_message`，便于定位误路由。

完整的新推荐、重复请求不继承旧型号或范围；有效追问只合并用户条件，不把旧答案注入模型。明确说“给这张显卡配主机”时才将上轮已核验显卡绑定为指定部件。新型号覆盖旧型号。单件推荐只展示该类别，普通游戏整机覆盖桌面 CPU/GPU；支持项仅保留主板平台、内存、供电／显示方案，不再展示存储、散热、机箱及其缺失提示。

介绍产品使用独立 `product_info` 路径：按型号检索本地资料目录，读取已接受的规格证据，经 TruthVerifier 核对后生成简短介绍和来源链接；不调用双路推荐或推荐文案模型。这是本地资料检索，不是实时外网搜索；未收录、规格无证据或型号歧义会明确说明，不能凭模型记忆补齐。前端独立展示介绍段落，避免“推荐理由／配置单”模板。

例如先问“给我推荐一套打游戏的配置”，再问“我想要50系NV显卡的配置”，后续核验保留游戏用途和整机范围，并筛选 RTX 50 系。指定 CPU/GPU 型号参与候选过滤；指定显卡时，CPU 检索根据数据库平衡规则反向筛选。后续明确替换型号会覆盖旧型号；旧推荐中的部件不会自动成为用户置顶项。通用配件要求同时传给两路模型；目前确定性型号识别限于代码支持的 CPU/GPU 命名格式。

数据库未命中或搭配规则不满足时，系统不应擅自替换指定硬件，也不应据此声称产品未发布。数据库、兼容性和证据核验仍然保留。

单件推荐、介绍专用路径及整机追问的本轮联调数据见 [意图优化验收](intent-optimization-validation-2026-09-17.md)。

后续针对本地 AI 场景的修复见 [模型意图与产品资料优化](model-intent-and-product-evidence-2026-09-17.md)。执行计划现在区分 `hardware/ai_model/general`，目标角色允许 `model`，分发调用使用 `temperature=0`；已有 GPU 是模型部署资源，只有明确购买显卡时才成为推荐对象。模型候选继续经双 Agent、真值核验及融合，不与 CPU/GPU 候选混合。产品介绍增加“目录收录、待补证据”的字段层级，缺少字段证据不再隐藏已经收录的全部规格；来源按实际支持字段展示。
