# 上下文窗口同步与文案精简

## 现状确认

用户指出的两处问题均存在：ModelProfile 以前只有配置窗口，没有 `/props` 探测；Agent 预检使用字符数 / 4，而历史上下文使用 ceil(字符数 / 2) + 4。

本轮只读实测 `agent-a` 与 `agent-b` 的 `/props.default_generation_settings.n_ctx` 都是 **16384**，`total_slots=1`；本地 `AGENT_DEFAULT_CONTEXT_SIZE=16384`，当前没有错配。`LLM_CONTEXT_WINDOW_TOKENS=32768` 是历史配置上限，实际历史预算现在取它与服务端窗口的较小值，不把 32768 当作当前模型窗口。

另一个问题是旧 `/tokenize` 输入为消息 JSON 文本，未套聊天模板，也漏了工具定义，不能算精确的模型输入 token 数。

## 实现

- 启动与每个新 Job 读取两台服务 `/props`；直接调用融合／快速问答、管理员端点查询和 Agent 预检也按缓存期限刷新。融合取得调度锁后刷新，避免排队时缓存过期。
- `default_generation_settings.n_ctx` 按每槽窗口使用，不再除以 `total_slots`；忽略顶层总容量、训练窗口、错误型号、布尔值、字符串和无效值。
- 缓存按完整端点与模型 ID 隔离；默认 30 秒，失败最多缓存 5 秒；每个探测超时 2 秒，两端点并行。失败回到配置值并将来源标记为 `settings`，成功标记为 `props`。不改写 `.env`，不操控推理设备参数。
- `ModelProfile.context_size` 和历史裁剪共享已发现窗口，历史默认取参与模型中的较小窗口；压缩阈值也与实际容量对齐。后台展示窗口数及“服务端／配置”来源。
- Agent 预检先调用 `/apply-template`（含 tools、生成前缀和关闭 thinking 的模板参数），再 `/tokenize`（解析特殊 token，不重复添加 BOS）。只在两个步骤均成功时使用精确值。
- 两处离线估算统一到 `inference/token_estimation.py`：UTF-8 字节数 / 2 向上取整，加 4 framing 余量，空串为 0。这是保守回退，不是实测 token，不能作为实时输出用量。
- 每次工具调用、候选选择与最后 JSON 生成都限制输出上限：不超过实际窗口减去输入 token 数。最后一次生成也补上预检。真实 SSE 输出 token 统计口径不变。

配置项：`CONTEXT_PROBE_ENABLED=true`、`CONTEXT_PROBE_TIMEOUT_SECONDS=2`、`CONTEXT_PROBE_TTL_SECONDS=30`。无 `/props` 的服务仍需正确设置 `AGENT_DEFAULT_CONTEXT_SIZE`。探测支持范围为当前 llama.cpp resident endpoints；无模板渲染能力的端点使用统一估算，不冒充精确计数。
