# 推荐数量与显式要求校验

本次修复三类请求：两张 NVIDIA 显卡分别偏性价比和高性能、明确要求不搜索数据库、至少 16GB 显存的 NVIDIA 显卡。

## 行为

- “不要搜索／检索／查询数据库”等显式要求优先于 auto、fusion 模式与历史推荐，跳过意图模型和硬件检索管线。聊天记录存取仍属于应用自身的会话持久化。
- 提取推荐数量、GPU 品牌及排除品牌、最低显存，数据库检索先过滤再截取。品牌从已核验的规范产品名称识别，无法识别时不视为满足指定品牌。
- 事实校验之后另行校验需求：12GiB 规格即使真实，也不能满足至少 16GB；缺少显存证据不能视为满足。消费级显存 GB 请求按目录 GiB 容量口径处理，MiB 显式转换。
- 多项推荐保留本次查询返回、具有字段证据绑定的候选，随后照常经过事实与硬约束核验。补充候选没有模型评分，不从模型记忆补型号。
- 两种偏好分别检索主流档次和高性能档次，核验后按库内性能分级选择不同产品。性价比方向只是主流档次备选，缺少当前售价时明确不能验证性价比。不会把唯一的旗舰候选填入性价比名额。
- 新增兼容旧接口的 `selections` 与 `selection_notice`。两项推荐均显示名称、方向、理由、证据及来源；不足时说明缺额。旧单项结果继续使用 `primary`。
- 显存问题不再自动解释成本地模型用途；移除无依据的“排序最优”兜底理由。

## 边界与进一步扩展

当前提取器覆盖明确数量、常见品牌表达和最低显存，不声称理解任意复杂自然语言。检索与交付的候选池最多保留 10 项。性价比排序需要同地区、同时间、同成色价格及可比性能数据，现有性能分级不能代替这些证据。

更复杂的组合条件应扩展为受限的结构化要求（字段、运算符、值、单位、原句位置），由模型辅助提取，再用确定性程序校验。否定、区间、条件分支及多轮条件覆盖需要各自回归样例。应分别检查“事实是否真实”“是否满足要求”“输出是否覆盖所有名额”，不可仅依靠模型自审或一个融合得分。

## 验证

新增后端回归覆盖禁用数据库、SQL 过滤、错误品牌、显存不足与缺证据、候选保留、数量、分组与缺额；前端新增两项推荐和缺额显示测试。测试采用 mock／内存数据，没有连接真实推理服务或硬件目录做端到端验收。

后端全量首次运行：558 passed、5 skipped；3 项既有目录契约测试因 pytest 临时目录权限错误未执行。前端 Vitest 与 Vite 构建因临时文件写权限失败；两类沙箱外重试均被自动审批拒绝。需显式批准后补验，不能把这些项目记为已通过。

后续相关回归覆盖协议候选保留、单一偏好数量及旗舰不能填补性价比名额。顺带修复了已有叙述测试随机 UUID 含 `999` 时误报的问题：断言只检查用户可见文字，不检查标识符。
