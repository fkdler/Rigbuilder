## 9800X3D 的根因与修复

| 层次 | 实际证据 | 修复 |
|---|---|---|
| 数据存在性 | cpu_catalog 有 Ryzen 7 9800X3D，原 Agent A 也查到了 | 不用重复补同型号数据掩盖问题 |
| 访问权限 | Agent 查询 performance_ranking 返回“对视图 performance_ranking 权限不够”，应用账号却能读取 | 补齐 16 个视图的只读授权和未来视图默认授权；仍禁止读取 truth/public 用户表 |
| 候选检索 | 按空发布日期、名称排序选到 Intel Arc A370M；模型把 X3D 当架构或去 GPU 表查询 9800 | 按角色、桌面形态、固定 SKU、现有搭配政策做有界检索；仍走 query_database、Evidence 绑定、TruthVerifier |
| 用户约束 | 重跑原问题得到 7950X3D + RTX 5090，错误替换指定 CPU | 独立型号与排除条件校验；未命中不擅自替换 |
| 融合 | 把 eliminated 候选重新放入配对池；无配对时固定删 CPU 留 GPU | 不复用硬约束/事实失败候选；保留已核验的指定 CPU 并显示缺口 |
| 中文识别 | “不要笔记本显卡”触发笔记本分支；CPU紧邻中文识别失败；“不玩游戏”被当作游戏 | 修复这些正反例并统一整机范围判定 |
| 模型能力 | 查询型号/字段错误；润色把 8 核变成“8 核 8 线程”，数字白名单未拦截 | 整机最终说明直接按核验字段生成；线程断言绑定 cpu.threads；解释追问保留额外事实说明 |
| 失败与展示 | 核验失败后再次自由生成清单；空结果、第四条以后的限制被隐藏 | 硬件失败使用明确的未核验答复；展示空结果和全部重要限制 |

这不是单一缺数据问题，也不能只归因于模型大小。已证实有权限、链路和模型查询/润色错误；未替换模型做同条件 A/B，不能宣称量化了不同模型的能力差距。
