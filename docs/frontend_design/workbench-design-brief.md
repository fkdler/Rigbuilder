# RigBuilder 推荐工作台设计简报

**目标**：将当前的浅色纸质工作台重新设计为终端风格的专业决策工作台

## 1. 工作与受众

**到达者**：需要硬件推荐决策的广泛用户（游戏玩家、学生、AI 爱好者等）

**情境**：用户面临硬件选择，需要基于可验证事实做出可信决策，而非依赖搜索引擎的不确定结果

**访客模式**：Operate - 用户要完成"提出需求 → 确认约束 → 获得推荐 → 检查证据"的任务

**心智模型**：这是一个专业决策工作台/查询终端，不是聊天网页，不是客服对话框

## 2. 结果与证明

**主要任务**：
1. 输入自然语言需求并设置结构化约束
2. 浏览经过多 Agent 共识和 Truth DB 验证的 Top-K 候选
3. 检查验证状态、证据覆盖、约束满足情况
4. 审查执行 trace 和融合过程

**成功标准**：用户能够基于透明的验证状态和可追溯的决策过程，自信地选择硬件配置

**真实证据**：
- Truth DB 中的 95 个硬件实体、799 条 accepted Evidence
- 三个 Agent 的独立推荐和验证状态
- fusion-v1 算法计算的 recommendation_score 和 credibility

**产品独特性**：多 Agent 共识 + Truth DB 验证 + 完整可追溯性，区别于搜索引擎和普通推荐工具

## 3. 选定方向

### 视觉定位
- **参考灵感**：Claude Code CLI 的秩序感、密度和命令感（但不复制其视觉细节、品牌元素、布局或文案）
- **身份**：专业决策工作台 / 查询终端 / 决策记录系统
- **反面参照**：ChatGPT 聊天界面、客服对话框、在线 LLM 网页

### 视觉系统

**色彩**：
- 底色：近黑但带暖色调（深炭黑、黑褐、墨灰），禁止纯黑配纯白
- 主文字：偏暖的灰白色
- 辅助文字：低饱和灰
- 状态色（少量使用）：
  - 磷光绿 → 成功/验证通过
  - 琥珀黄 → 进行中/警告
  - 砖红 → 风险/失败/冲突

**禁止元素**：
- 蓝紫渐变、发光光晕、玻璃拟态
- 粒子、矩阵雨、赛博网格、复杂连线背景
- 机器人图标、炫技数据可视化
- 圆角大卡片和卡片嵌套

**背景质感**：
- 保持干净
- 可用极弱的扫描线、纸张颗粒或终端噪点
- 不影响可读性，不依赖图片资源

**排版**：
- **混合排版策略**：
  - 等宽字体：命令、标签、数值、状态、trace、技术术语
  - 系统无衬线：长中文说明、推荐理由、风险描述
  - 避免整页中文等宽字体
- 不使用 Inter，不新增在线字体依赖
- 使用系统字体：`"SF Mono", "Consolas", "Liberation Mono", Menlo, monospace`（等宽）+ `"Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei", system-ui, sans-serif`（无衬线）

**结构工具**：
- 细分隔线、对齐、留白、编号
- 克制的符号排版：`//`、`[ ]`、`──`、`>` 等，服务于信息层级
- 圆角很小或不使用
- 避免圆角大卡片

### 信息架构

**1. 顶部终端式身份栏（紧凑）**
```
[ASCII Art Logo]    Release: rigbuilder-v3-2-2026-09-07    Status: OK    [New Session] [Sessions]
```
包含：
- 产品名（用彩色符号绘制成 ASCII Art 风格，类似终端 CLI 工具）
- 当前数据 Release
- 服务状态
- 会话操作：新建会话、切换会话的可交互 UI（不是 CLI 命令）

**2. 主查询区域**
- 清晰的大输入区
- 提交动作 + 快捷键提示（如 Ctrl+Enter）
- 已确认约束的结构化清单（而非装饰标签堆）

**3. Agent 执行状态**
- 三个 Agent 的可扫描状态
- 不伪造实时日志
- 显示模型 ID、状态、候选数、验证项数

**4. 融合结果区（重点）**
- **Top-K 候选**，每项包含：
  - 排名 + 候选名称
  - recommendation_score（推荐得分）
  - credibility（可信度），明确二者含义不同
  - 硬约束满足状态（satisfied / violated / unknown）
  - 关键验证指标：fact_support、proof_coverage、information_completeness
  - 风险与淘汰原因
  - 可展开：详细 Claims、证据 ID、Truth DB canonical 值、来源模型
- **淘汰候选**（折叠或独立区域）
- 不把所有信息塞进嵌套卡片

**5. Trace 查看器（可展开）**
- Agent 执行详情
- 融合公式和策略版本
- 输入摘要
- Agent coverage

### 交互模式

**呈现为"决策会话记录"或"查询日志"**：
- 问题、确认约束、执行进度、结果摘要有明确层次
- 不使用左右聊天气泡、机器人头像、打字机动画
- 不使用大面积空白消息流

**状态处理**：
- 空态：清晰的引导，说明系统能力
- 加载态：Agent 执行状态，不伪造进度
- 失败态：
  - 409 Truth Release 不可用 → 说明数据条件不满足
  - 503 配置错误 → 说明服务配置问题
  - HTTP 200 但 status: failed → 三个 Agent 都失败
  - 部分失败 → 展示 Agent coverage，标明哪些 Agent 失败
- 无结果：明确说明未找到满足约束的候选

## 4. 范围与边界

**目标**：`frontend/src/views/RecommendationWorkbench.vue` 及相关组件的完整重新设计

**保真度**：生产就绪代码，非原型

**广度**：推荐工作台单一页面，包含输入、状态、结果、trace 的完整流程

**交互性**：
- 键盘可访问所有关键操作
- 可展开/折叠详细信息
- 窄屏响应式：按"查询与约束 → 执行状态 → 推荐结果 → 依据"顺序单列排列

**保持不变**：
- `backend/` 不修改
- API 契约严格遵循 `docs/API_documents/API_Documentation_V3.1.md`
- 不修改 `docs/`、数据库 schema
- Vue 3 + TypeScript + Element Plus + Pinia + Axios 技术栈

**明确反目标**：
- 不做成 ChatGPT 式聊天界面
- 不添加机器人角色或对话式元素
- 不伪造验证状态、证据或排名
- 不使用装饰性科技图形（网格、粒子、发光）

## 5. 状态与范围

**真实内容范围**：
- 需求输入：1-4000 字符自然语言
- 约束：0-N 条结构化约束（field / price / compatibility / runtime）
- Top-K 候选：1-10 个（用户可配置，默认 3）
- 淘汰候选：0-N 个
- Agent：固定 3 个，状态为 completed / failed
- Claims：每个候选 0-N 条，每条有验证状态
- 证据：每条 Claim 可能有 0-N 个 evidence_id

**关键状态**：
- **空态**（idle）：等待用户输入
- **提交态**（submitting）：正在发送请求
- **执行态**（running）：三个 Agent 正在执行
- **完成态**（completed）：至少一个 Agent 成功，有融合结果
- **部分失败态**（partial_success）：部分 Agent 失败但有结果
- **失败态**（failed）：三个 Agent 全部失败或无结果
- **错误态**：409 / 503 / 其他 HTTP 错误

## 6. 交互与布局

**层级**：
1. 顶部身份栏（固定，紧凑）
2. 查询输入区（清晰，视觉主体之一）
3. 约束清单（结构化，可编辑）
4. Agent 执行状态（可扫描）
5. Top-K 结果（视觉主体，重点展示）
6. 淘汰候选（次要，可折叠）
7. Trace（次要，可展开）

**拓扑**：
- 桌面端：单列垂直流，宽度适中（不要全屏宽）
- 窄屏：保持单列，按任务优先级重排

**响应式断点**：
- 桌面：>= 1024px
- 平板：768px - 1023px
- 手机：< 768px

**交互反馈**：
- 提交：短暂过渡，无弹跳
- 展开：平滑展开，不使用华丽动画
- 状态切换：清晰的视觉反馈

**辅助功能**：
- 键盘导航：Tab、Enter、Esc
- 颜色 + 文字双重编码状态
- 语义化 HTML

## 7. 约束与未决事项

**平台**：Web（现代浏览器）

**交付**：Vue 3 SFC 组件 + TypeScript + 局部 scoped CSS

**无障碍**：
- WCAG 2.1 AA 目标
- 键盘可访问
- 颜色对比度符合标准
- 状态不依赖颜色单一表达

**技术约束**：
- 不新增 npm 依赖
- 不引入在线字体
- 继续使用 Element Plus 组件库（但覆盖样式以符合终端风格）

**复用组件**：
- ConstraintEditor.vue（需要重新设计为终端风格）
- RecommendationCard.vue（需要重新设计为高密度数据行）
- TraceViewer.vue（需要重新设计为结构化日志）

**新增功能**：
- **会话管理**：支持新建会话、切换历史会话
  - 使用可交互 UI（按钮、下拉菜单、侧边栏等），不是 CLI 命令
  - 会话列表显示：会话 ID、创建时间、最后一次查询摘要
  - 切换会话时加载该会话的上下文和历史结果
  - localStorage 持久化当前会话 ID
- **ASCII Art Logo**：将 "RIGBUILDER" 用彩色符号绘制成终端风格的 ASCII 艺术字

**待确认决策**：
- Agent 执行状态的详细程度（紧凑 vs 结构化日志）
- 推荐结果的首屏信息密度（高密度 vs 分层披露）
- 符号排版的具体使用（哪些区域用何种符号）
- 扫描线/噪点质感的具体强度
- 会话切换 UI 的具体形式（下拉菜单 vs 侧边栏 vs 模态框）

**明确约束**：
- 严格遵循 `docs/API_documents/API_Documentation_V3.1.md`
- 不修改 TypeScript 类型定义（已在 `frontend/src/api/agentFusion.ts`）
- 不修改 Pinia store 逻辑（已在 `frontend/src/stores/recommendation.ts`）
- 只修改视觉层、布局和交互反馈
